# Stalled background pages get full speed by being shown, not by switching throttling off

Zen throttles hidden tabs hard (no animation frames, timers about once a second, no `IntersectionObserver` updates), and nothing turns that off per session: WebDriver BiDi has no visibility or focus emulation, and the throttling prefs would have to be written into the user's profile (see ADR-0004). A page only runs at full speed when macOS shows it. So `new_tab` stays a throttled background tab by default, and agents opt in to one of two helpers: `in_front()` shows the agent's tab for a block and then re-selects the user's tab (but `browsingContext.activate` also brings Zen in front of the user's current app), or `new_window()` gives the agent a Zen window of its own, the same size and place as the user's, which runs at full speed while it is on screen and not covered by another app (Zen windows don't count as covering). BiDi's `browsingContext.create` with `type: "window"` fails in Zen ("openWindow() not supported in Zen"), so `new_window` has the page open a popup from a click in a throwaway tab, and `new_tab` steers new tabs away from popup windows.
